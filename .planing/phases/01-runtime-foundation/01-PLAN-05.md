<task id="T1" type="execute">
  <title>Pre-flight checks (automated, on macOS ARM64 terminal)</title>
  <read_first>
    - `requirements-macos.txt` — confirm the file content before install
    - `docs/macos/SETUP_MACOS.md` — check for any existing macOS setup instructions that should be followed first
  </read_first>
  <action>
    On the Apple Silicon Mac, in a clean Python 3.12 virtual environment (native ARM64 — NOT via Rosetta), run these pre-flight checks in sequence:

    **Check 1 — Confirm native ARM64 Python:**
    ```bash
    python3 -c "import platform; print(platform.machine())"
    # Must print: arm64
    # If it prints x86_64, Python is running under Rosetta — reinstall from python.org ARM64 installer
    ```

    **Check 2 — Install dependencies:**
    ```bash
    python3 -m venv .venv-macos
    source .venv-macos/bin/activate
    pip install -r requirements-macos.txt
    # Must complete with no errors
    ```

    **Check 3 — Verify pyvips (not silent PIL fallback):**
    ```bash
    python3 -c "import pyvips; print('pyvips version:', pyvips.__version__)"
    # Must print a version string (e.g., 3.1.1)
    # If ImportError or 'libvips not found' → pyvips-binary not installed correctly
    ```

    **Check 4 — Verify OpenSlide:**
    ```bash
    python3 -c "import openslide; print('openslide path:', openslide.OPENSLIDE_PATH)"
    # Must print a path ending in .dylib or .so (not None)
    # If None → openslide-bin dylib not discovered; may need DYLD_LIBRARY_PATH workaround
    ```

    **Check 5 — Verify PyTorch + MPS:**
    ```bash
    python3 -c "import torch; print('torch:', torch.__version__); print('MPS available:', torch.backends.mps.is_available())"
    # Must print torch version without +cu124
    # MPS available: True (on M1/M2/M3)
    # MPS available: False is acceptable only on Intel Mac (out of scope — but log it)
    ```

    **Check 6 — Verify NuClick device path:**
    ```bash
    python3 -c "
    from app.infrastructure.ml_models.nuclick_adapter import _get_device
    device = _get_device()
    print('NuClick will use device:', device)
    # Expected: device('mps') on Apple Silicon with MPS available
    # Acceptable: device('cpu') if MPS unavailable
    "
    ```

    Record all output. If any check fails, document the exact error message.
  </action>
  <acceptance_criteria>
    - `platform.machine()` returns `arm64`
    - `pip install -r requirements-macos.txt` exits 0 with no ERROR lines
    - `pyvips.__version__` prints without ImportError
    - `openslide.OPENSLIDE_PATH` is not None
    - `torch.__version__` does not contain `+cu124`
    - `torch.backends.mps.is_available()` returns True (on Apple Silicon)
  </acceptance_criteria>
</task>

<task id="T2" type="checkpoint:human-verify">
  <title>Verify app launches and segmentation works on Apple Silicon</title>
  <what-built>
    Plans 01-04 fixed dependencies and patched NuClickAdapter and CellposeAdapter for MPS.
    Plan 05 T1 ran automated pre-flight checks. This checkpoint verifies the full app experience on macOS ARM64.
  </what-built>
  <how-to-verify>
    On the Apple Silicon Mac, with the virtual environment activated:

    **Step 1 — Launch the app (RUN-01, RUN-02):**
    ```bash
    python3 main.py
    ```
    Expected: Main window opens. No crash. No unhandled exception in terminal.

    **Step 2 — Load a standard image (RUN-03):**
    - File > Open (or drag-and-drop) a PNG or JPEG file.
    - Expected: Image renders in the viewport. No error dialog. Terminal should NOT print "pyvips not installed or missing libvips — falling back to PIL".

    **Step 3 — Load a whole-slide image if available (RUN-04):**
    - Open a .ndpi, .svs, or .mrxs file.
    - Expected: WSI loads and renders a tile. No OpenSlide error.
    - If no WSI file is available, skip this step and note it in the response.

    **Step 4 — Run Cellpose segmentation (RUN-05):**
    - With an image loaded, select Cellpose in the model dropdown.
    - Run segmentation.
    - Expected: Segmentation completes and polygons appear on the image. Check terminal for device being used (mps or cpu).
    - If MPS sparse tensor error occurs and CPU fallback triggers, that is an acceptable pass (fallback is working).

    **Step 5 — Run NuClick segmentation (RUN-06):**
    - Switch to NuClick mode.
    - Click on a nucleus in the image.
    - Expected: A polygon appears around the clicked nucleus. Check terminal for "NuClick model loaded successfully from ... on mps" or "on cpu".
  </how-to-verify>
  <resume-signal>
    Type "approved" if all five steps pass.
    Type "partial: [list which steps passed/failed]" if some steps pass.
    Type "failed: [exact error message]" if a step hard-fails.

    For each failure, include the exact terminal output so gap-closure plans can target the right issue.
  </resume-signal>
</task>
