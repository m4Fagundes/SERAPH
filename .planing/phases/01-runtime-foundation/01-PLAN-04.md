<objective>
Patch `app/infrastructure/ml_models/cellpose_adapter.py` to extend the existing GPU→CPU fallback path to also cover MPS failures (specifically the `NotImplementedError` for sparse tensor ops on Apple Silicon).

Purpose: `CellposeAdapter` already has an MPS detection path in `_runtime_gpu_available()` (lines 89–90). The model will load and run forward inference on MPS. But Cellpose 4.x's mask creation code calls sparse tensor ops that MPS does not support, raising `NotImplementedError`. The current `_is_cuda_oom` static method only catches CUDA OOM messages — MPS errors slip through and surface as uncaught exceptions. RUN-05 requires Cellpose to run on MPS or CPU; this patch ensures the CPU fallback triggers on MPS failures too. No functional change on Windows/CUDA paths.

Output: Modified `cellpose_adapter.py` with `_is_gpu_failure` replacing `_is_cuda_oom`, two call sites updated.
</objective>

<!-- Target replacement from research (01-RESEARCH.md, CellposeAdapter MPS failure detection): -->
```python
@staticmethod
def _is_gpu_failure(exc: Exception) -> bool:
    """Returns True if exc is a GPU error that should trigger CPU fallback.

    Covers:
    - CUDA out-of-memory errors (existing behavior)
    - cuDNN errors (existing behavior)
    - MPS NotImplementedError for unsupported ops (e.g., sparse tensors in
      Cellpose 4.x mask creation — see github.com/MouseLand/cellpose/issues/1063)
    """
    msg = str(exc).lower()
    return (
        "cuda out of memory" in msg
        or "cudnn error" in msg
        or "not implemented" in msg       # MPS: NotImplementedError for sparse ops
        or "could not run" in msg         # MPS: "Could not run 'aten::...' with arguments from the 'SparseMPS' backend"
    )
```
