# 🔬 Cell Nuclei Segmentation & Grid Analyzer
**Image and Multimedia Data Science Laboratory (IMSCIENCE)**

## 🎓 About the Project

This project was developed by **Matheus Fagundes** under the **Scientific Initiation Program** at the **IMSCIENCE** laboratory.

**Primary Objective:** To provide a fast, reliable, and highly accurate tool for **segmenting (delimiting with the lowest possible error) cell nuclei** in gigantic high-resolution images (often ranging from hundreds of megabytes to gigabytes, such as *Whole Slide Images* - WSI).

## 🌟 What Can You Do With This Tool?

Designed to handle extremely heavy microscopy images that natively exceed standard RAM limits, scientists and pathologists can use this software to:
- **Open Giant Images Instantly:** Load medical/scientific formats (`.ndpi`, `.svs`, `.tif`, `.mrxs`) without exhaustive initial parsing times.
- **Isolate Regions of Interest (ROI):** Use an interactive, dynamic grid to slice biological tissues into manageable sub-regions for specific assays or AI training.
- **Annotate & Outline Nuclei:** Bridge local Machine Learning interactive models (like *NuClick* or *SAM*) to click or encircle cells, generating precise polygons and cellular masks in real-time.
- **Manually Correct AI Errors:** Use pixel-neighborhood brush tools and manual interactive segmentation borders to fix any flaws generated by the algorithm.
- **Extract Spatial Metadata:** Input the exact physical micron scale (µm/px) to generate reliable scale bars and physical size metrics for cells.
- **Export "ML-Ready" Datasets:** A single click exports the parsed tissues, bounding boxes, polygon masks, CSV, and JSON metadata directly compatible with computational pipelines like *PyTorch* or *TensorFlow*.

## ⚙️ Core Architecture (Clean / Hexagonal)

To ensure this complex software remains maintainable and decoupled from the Tkinter GUI, the codebase strictly adheres to **Clean Architecture** patterns, divided into four rigid layers:

1. **Domain Layer (`app/domain`):** Pure Python business logic devoid of UI or disk dependencies. It houses the geometric logic (`geometry.py`), state control for undo/redo (`history.py`), and mathematical models representing grids, coordinates, and cell data (`tile.py`, `session.py`).
2. **Application Layer (`app/application`):** The *Use-Case* orchestrators. Files like `interactive_segmentation_service.py` and `export_service.py` mediate the user's intent to perform actions on the domain entities, without knowing how they are rendered.
3. **Infrastructure Layer (`app/infrastructure`):** Handles heavy external I/O and libraries. Wraps the low-level C behaviors of `pyvips` encoding (`io.py`), parses pathology xml files (`tile_xml.py`), and communicates with local ML inference instances (`ml_models/`).
4. **Interface / Presentation Layer (`app/interface/gui`):** The entire Tkinter GUI ecosystem. Responsibilities are split dynamically depending on the OS (e.g., using `ttk` styles for Ubuntu, dark-mode heuristics on macOS via `utils.py`) to manage a lightweight canvas while delegating synchronous operations to the Application layer.

## 🏗️ Architectural Deep Dive: Main Features

### 1. Viewport-Only Multiscale Rendering Engine
Due to the massive footprint of WSI (Whole Slide Images), loading the source file into memory is impossible. 
- **The Pipeline:** The GUI Canvas asks the Application layer for an image chunk based on current `(x, y)` coordinate offsets and zoom magnitude.
- **Infrastructure Translation (`pyramid.py` & `pyvips` / `OpenSlide`):** Rather than reading the entire image, the infrastructure selectively decodes only the bounded pixel box covering the user's viewport. 
- **Hybrid Zoom Strategy:** 
  - *Below 50% Zoom*: The engine reads from a pre-calculated lossy pyramid layer for rapid scrolling and macroscopic panning.
  - *Above 50% Zoom*: It fetches cropping data from the absolute highest resolution native layer and applies *Lanczos* filtering to prevent interpolation artifacts, ensuring the pathologist sees pristine cell walls.

### 2. Smart Grid Selection & BFS Disconnection
When a user draws a rubber-band box across a grid to select hundreds of ROIs at once, they may later delete specific middle grid cells.
- **The Problem:** Deleting a central cell could split a single large ROI polygon into two distinct biological groups.
- **Domain Solution (`selection.py`):** Modifying a cell matrix triggers an underlying **Breadth-First Search (BFS) Flood-fill algorithm**. The domain layer scans the 4-connected spatial neighborhood of all currently selected cells. If the BFS detects that a monolithic tile has fundamentally fractured into non-adjacent islands, it automatically splits them into distinct software entities, subsequently assigning them unique identification colors through the system.

### 3. Interactive Machine Learning Segmentation (NuClick/SAM)
Bridging Python GUI clicks to complex deep-learning inference.
- **The Flow:** When the user utilizes the NuClick mode, a screen coordinate `(x_gui, y_gui)` is generated via the Tkinter Canvas.
- **Coordinate Mapping:** The GUI passes it to `interactive_segmentation_service.py`. The service leverages the Domain layer to translate the monitor's coordinate—factoring in the current zoom scale, camera offset, and DPI padding—into an absolute source-image pixel coordinate `(X_img, Y_img)`.
- **Inference (`app/infrastructure/ml_models`):** The exact coordinate region is sent to the local model. The model calculates the cellular blob and returns a boundary mask. The Application layer converts this boolean mask into a vector polygon (using contour-finding algorithms) and injects it back into the GUI.

### 4. Stack-Based Undo / Redo Mechanism
To maintain high performance without blocking the UI, a deep-copy snapshot system was introduced.
- **Domain Integration (`history.py`):** Before any mutating operation is committed (erasing a cell, drawing a new manual segment, splitting nodes), a `deepcopy` of the current `ImageSession` mathematical states (polygons, grid matrices, color markers) is pushed onto a capped memory stack (maximum 50 iterations limit). 
- **Time Complexity:** Instead of creating computationally intensive action-inverters, swapping the active domain instance reference to the previous state takes $O(1)$ time, allowing instant `Ctrl+Z` rollbacks seamlessly.

### 5. Persistent Session Management (`.lab` Projects)
The workspace context leverages an isolated JSON serialization strategy.
- When saving a project, the internal `session.py` entities are compacted into relative JSON nodes.
- **Portability:** Path variables are structured relatively. If researchers share a folder containing both `.lab` files and `.svs` images over internal servers, the application dynamically resolves the relative anchors regardless of the absolute mount point.

## 📦 How to Run the Tool (OS Specifics)

This system has been structurally adapted to run on **macOS** (with Magic Mouse native gesture mapping), **Linux**, and **Windows**.

### General Prerequisites
- Python **3.8 or higher**
- `Pillow` (PIL)
- *Heavy Native C Binaries* - `openslide` and `vips` (These cannot be installed purely via python, they require OS-level package managers to supply the C-headers).

### 🪟 Windows Setup (Most Automated)
On Windows, pip handles most of the C-binding binaries natively through pre-compiled wheels.

```powershell
# 1. Clone the repository
git clone https://github.com/imscience/grid-image-analyzer.git
cd grid-image-analyzer

# 2. Install Python dependencies (including Windows pre-compiled bindings)
pip install Pillow pyvips openslide-bin openslide-python

# 3. Launch the App
python main.py
```

### 🍏 macOS Setup (Homebrew Required)
Apple Silicon (M1/M2/M3) and Intel macs require Homebrew to properly link the C-render engines before python interacts with them to prevent memory faults.

```bash
# 1. Clone the repository
git clone https://github.com/imscience/grid-image-analyzer.git
cd grid-image-analyzer

# 2. Install the raw C-engines via Homebrew (Mandatory step)
brew install vips openslide

# 3. Install the Python Wrappers
pip install Pillow pyvips openslide-python

# 4. Launch the App (Use python3 explicitly)
python3 main.py
```

### 🐧 Linux Setup (Debian/Ubuntu)

```bash
# 1. Install system architecture dependencies via APT
sudo apt update
sudo apt install libvips-dev libvips openslide-tools

# 2. Install Python Wrappers
pip install Pillow pyvips openslide-python

# 3. Launch the App
python3 main.py
```

## 🎮 Workflow & Shortcuts

- **Pan Camera:** Left-click & Drag.
- **Directional Pan:** `Mouse Wheel` (Vertical) | `Shift` + `Mouse Wheel` (Horizontal).
- **Dynamic Zoom (Centered on Cursor):** `Ctrl` + Scroll (Windows) | `Cmd/Option` + Scroll (macOS).
- **Add / Remove AI Nuclei Marking:** Right-Click (`Button-3` Windows | `Button-2` or `Ctrl+Click` on macOS).
- **Clear All Polygons & Grid States:** Press the `C` key.
- **Undo / Redo:** `Ctrl+Z` / `Ctrl+Y`.
